PART 1 — Understanding Old JavaScript vs Modern JavaScript
1. What is Old JavaScript?
JavaScript was originally developed by Brendan Eich in 1995.

Over time, JavaScript evolved significantly.

When developers say:
- Old JavaScript
- Traditional JavaScript
- Modern JavaScript
- New JavaScript
- ES6 JavaScript
They are generally referring to different generations of JavaScript syntax and features.

There isn't an official programming language called Old JavaScript or New JavaScript.

The official standard is called ECMAScript (ES).
What is ECMAScript?
ECMAScript is the standard specification that defines how JavaScript should work.

JavaScript is an implementation of that standard.

Think of it this way:
Term	Meaning
JavaScript	Programming language
ECMAScript	JavaScript language specification
ES5	Older JavaScript standard (2009)
ES6 / ES2015	Major JavaScript update (2015)
ES2016+	Features introduced in later yearly updates
ESNext	Upcoming or recently proposed JavaScript features


Important JavaScript versions
Version	Year	Important features
ES3	1999	Basic JavaScript features
ES5	2009	Strict mode, JSON, array methods
ES6 (ES2015)	2015	let, const, arrow functions, classes, promises, modules
ES2016	2016	includes(), exponentiation
ES2017	2017	async/await
ES2018	2018	Rest/spread for objects, Promise.finally
ES2019	2019	flat(), flatMap(), Object.fromEntries()
ES2020	2020	Optional chaining, nullish coalescing, BigInt
ES2021	2021	replaceAll(), Promise.any()
ES2022	2022	Top-level await, private class fields
ES2023	2023	findLast(), toSorted()
ES2024	2024	Object.groupBy(), Promise.withResolvers()


Important: ES6 was a major turning point, but modern JavaScript includes many features introduced after ES6.
PART 2 — Old JavaScript vs Modern JavaScript
Let's understand the differences practically.
2.1 Variable Declaration: var vs let vs const
Old JavaScript
Before ES6, developers primarily used var.
var name = "Haris";
var age = 25;

console.log(name);
console.log(age);

Modern JavaScript
ES6 introduced let and const.
let name = "Haris";
const age = 25;

console.log(name);
console.log(age);

Difference
Feature	var	let	const
Reassignment	Yes	Yes	No
Redeclaration in same scope	Yes	No	No
Function scoped	Yes	No	No
Block scoped	No	Yes	Yes
Must initialize immediately	No	No	Yes


Understanding scope
Consider this example:
if (true) {
    var a = 10;
    let b = 20;
    const c = 30;
}

console.log(a); // 10

console.log(b); // ReferenceError
console.log(c); // ReferenceError

Why?

Because:
- var is function-scoped.
- let is block-scoped.
- const is block-scoped.
A block is generally defined by { }.
Important: const with objects
Many beginners think that const makes an object completely unchangeable.

That's incorrect.
const user = {
    name: "Haris",
    age: 25
};

user.age = 26; // Allowed

console.log(user);

But you cannot reassign the variable:
user = {}; // Error

Best practice:
- Use const by default.
- Use let when reassignment is required.
- Avoid var in modern development.
PART 3 — Functions in Modern JavaScript
Functions are extremely important in React, Next.js and Node.js.

You should understand all their forms.
3.1 Function Declaration
Traditional JavaScript:
function greet() {
    console.log("Hello Haris");
}

greet();

PHP comparison:
function greet() {
    echo "Hello Haris";
}

greet();

Both are similar.
3.2 Function Expression
const greet = function() {
    console.log("Hello Haris");
};

greet();

Here, we assign a function to a variable.
3.3 Arrow Functions (ES6)
Arrow functions are one of the most frequently used modern JavaScript features.

Old JavaScript:
function add(a, b) {
    return a + b;
}

Modern JavaScript:
const add = (a, b) => {
    return a + b;
};

Even shorter:
const add = (a, b) => a + b;

console.log(add(10, 20)); // 30

Different arrow function examples
One parameter:
const square = number => number * number;

console.log(square(5)); // 25

Multiple parameters:
const multiply = (a, b) => a * b;

No parameters:
const sayHello = () => {
    console.log("Hello");
};

Returning an object:
const getUser = () => ({
    name: "Haris",
    age: 25
});

Notice the parentheses around the object.
Why are arrow functions important?
You'll see them everywhere in React.

Example:
function User() {
    return <h1>Hello Haris</h1>;
}

Modern style:
const User = () => {
    return <h1>Hello Haris</h1>;
};

And in event handlers:
<button onClick={() => console.log("Clicked")}>
    Click Me
</button>

Important difference: Arrow functions vs normal functions
Arrow functions do not have their own:
- this
- arguments
- super
- new.target
They inherit this from their surrounding lexical scope.

We'll discuss this later.
3.4 Default Parameters
Old JavaScript:
function greet(name) {
    name = name || "Guest";

    console.log("Hello " + name);
}

greet();

Modern JavaScript:
function greet(name = "Guest") {
    console.log(`Hello ${name}`);
}

greet();        // Hello Guest
greet("Haris"); // Hello Haris

This is cleaner and easier to maintain.

You'll use default parameters in React components:
function User({ name = "Guest" }) {
    return <h1>Hello {name}</h1>;
}

PART 4 — Template Literals
4.1 Old JavaScript
Previously, developers used string concatenation.
var name = "Haris";
var age = 25;

var message = "My name is " + name + " and my age is " + age;

console.log(message);

4.2 Modern JavaScript
ES6 introduced template literals using backticks.
const name = "Haris";
const age = 25;

const message = `My name is ${name} and my age is ${age}`;

console.log(message);

Benefits
You can:
1. Insert variables.
2. Perform calculations.
3. Write multiline strings.
4. Write expressions directly.
Example:
const price = 100;
const quantity = 5;

console.log(`Total: ${price * quantity}`);

Multiline example:
const message = `
    Hello Haris,
    Welcome to JavaScript.
    Happy Learning!
`;

console.log(message);

Where used?
- React
- Next.js
- Node.js
- HTML templates
- Dynamic messages
- API responses
PART 5 — Destructuring
Destructuring is one of the most important concepts in modern JavaScript.

You'll use it constantly in React and Next.js.

There are two major types:
1. Array destructuring
2. Object destructuring
5.1 Array Destructuring
Old JavaScript:
const colors = ["Red", "Green", "Blue"];

const first = colors[0];
const second = colors[1];
const third = colors[2];

console.log(first);

Modern JavaScript:
const colors = ["Red", "Green", "Blue"];

const [first, second, third] = colors;

console.log(first);
console.log(second);
console.log(third);

Skipping values
const numbers = [10, 20, 30];

const [first, , third] = numbers;

console.log(first); // 10
console.log(third); // 30

Default values
const [name = "Guest", age = 20] = ["Haris"];

console.log(name); // Haris
console.log(age);  // 20

5.2 Object Destructuring
Old JavaScript:
const user = {
    name: "Haris",
    age: 25,
    city: "Pakistan"
};

const name = user.name;
const age = user.age;

Modern JavaScript:
const user = {
    name: "Haris",
    age: 25,
    city: "Pakistan"
};

const { name, age, city } = user;

Rename variables
const user = {
    name: "Haris",
    age: 25
};

const { name: userName, age: userAge } = user;

console.log(userName);
console.log(userAge);

Default values
const user = {
    name: "Haris"
};

const { name, age = 25 } = user;

Nested destructuring
const user = {
    name: "Haris",
    address: {
        city: "Wah Cantt",
        country: "Pakistan"
    }
};

const {
    name,
    address: { city, country }
} = user;

console.log(city);
console.log(country);

Where used in React?
This is extremely important.
function User({ name, age, city }) {
    return (
        <div>
            <h2>{name}</h2>
            <p>{age}</p>
            <p>{city}</p>
        </div>
    );
}

Here, we're destructuring component props.

You should become very comfortable with object and array destructuring.
PART 6 — Spread and Rest Operators
Both use the same three-dot syntax:

...

But they have different purposes.
6.1 Spread Operator
Spread expands an array or object.
Old JavaScript
var numbers1 = [10, 20, 30];
var numbers2 = [40, 50, 60];

var result = numbers1.concat(numbers2);

console.log(result);

Modern JavaScript
const numbers1 = [10, 20, 30];
const numbers2 = [40, 50, 60];

const result = [...numbers1, ...numbers2];

console.log(result);

Output:
[10, 20, 30, 40, 50, 60]

Copy an array
const original = [10, 20, 30];

const copied = [...original];

Copy an object
const user = {
    name: "Haris",
    age: 25
};

const updatedUser = {
    ...user,
    age: 26
};

console.log(updatedUser);

Why important in React?
React encourages immutable state updates.

Example:
const [user, setUser] = useState({
    name: "Haris",
    age: 25
});

function updateAge() {
    setUser({
        ...user,
        age: 26
    });
}

Instead of directly modifying the existing object, we create a new object.
6.2 Rest Operator
Rest collects multiple values into an array or object.

Example:
function sum(...numbers) {
    return numbers.reduce((total, number) => total + number, 0);
}

console.log(sum(10, 20, 30, 40));

Output:
100

Rest with destructuring
const numbers = [10, 20, 30, 40, 50];

const [first, second, ...remaining] = numbers;

console.log(first);
console.log(second);
console.log(remaining);

Output:
10
20
[30, 40, 50]

Spread vs Rest
Spread	Rest
Expands values	Collects values
Used when passing or copying values	Used when receiving values
Common in arrays and objects	Common in function parameters and destructuring


PART 7 — Array Methods
This is one of the most important sections.

Modern JavaScript development heavily depends on array methods.

In React, you'll use them for displaying lists, filtering products, searching, updating records and more.

Let's understand every important method.

Assume we have this array:
const products = [
    {
        id: 1,
        name: "iPhone 15",
        price: 800,
        category: "Mobile"
    },
    {
        id: 2,
        name: "Samsung S24",
        price: 900,
        category: "Mobile"
    },
    {
        id: 3,
        name: "MacBook Pro",
        price: 1500,
        category: "Laptop"
    },
    {
        id: 4,
        name: "iPad",
        price: 600,
        category: "Tablet"
    }
];

7.1 forEach()
Executes a function for every array element.
products.forEach((product) => {
    console.log(product.name);
});

PHP comparison:
foreach ($products as $product) {
    echo $product['name'];
}

Important:

forEach() does not return a new array.
7.2 map()
Creates a new array by transforming every element.
const names = products.map((product) => {
    return product.name;
});

console.log(names);

Output:
[
    "iPhone 15",
    "Samsung S24",
    "MacBook Pro",
    "iPad"
]

Short version:
const names = products.map(product => product.name);

React example
function Products() {
    const products = ["iPhone", "Samsung", "MacBook"];

    return (
        <div>
            {products.map((product, index) => (
                <h2 key={index}>{product}</h2>
            ))}
        </div>
    );
}

Remember: map() is extremely important for rendering lists in React.

For real database records, prefer a stable unique ID for the React key rather than the array index.
7.3 filter()
Returns a new array containing elements that satisfy a condition.

Example:
const expensiveProducts = products.filter(product => {
    return product.price > 800;
});

console.log(expensiveProducts);

Short version:
const expensiveProducts = products.filter(p => p.price > 800);

PHP comparison:
$filteredProducts = array_filter($products, function($product) {
    return $product['price'] > 800;
});

7.4 find()
Returns the first matching element.
const product = products.find(p => p.id === 2);

console.log(product);

Output:
{
    id: 2,
    name: "Samsung S24",
    price: 900,
    category: "Mobile"
}

Difference between find() and filter():
- find() returns one matching element.
- filter() returns an array of matching elements.
7.5 findIndex()
Returns the index of the first matching element.
const index = products.findIndex(p => p.id === 3);

console.log(index); // 2

7.6 reduce()
One of the most powerful array methods.

It reduces an array into a single value.

Example: Calculate total product price.
const total = products.reduce((sum, product) => {
    return sum + product.price;
}, 0);

console.log(total); // 3800

Explanation:
reduce((accumulator, currentValue) => {}, initialValue);

Parameter	Meaning
accumulator	Stores the accumulated result
currentValue	Current array element
initialValue	Starting value


Another example: Count products
const totalProducts = products.reduce((count) => {
    return count + 1;
}, 0);

Group products by category
const grouped = products.reduce((result, product) => {
    const category = product.category;

    if (!result[category]) {
        result[category] = [];
    }

    result[category].push(product);

    return result;
}, {});

console.log(grouped);

7.7 some()
Checks whether at least one element satisfies a condition.
const hasExpensiveProduct = products.some(p => p.price > 1000);

console.log(hasExpensiveProduct); // true

7.8 every()
Checks whether all elements satisfy a condition.
const allAvailable = products.every(p => p.price > 0);

console.log(allAvailable); // true

7.9 includes()
Checks whether an array contains a particular value.
const fruits = ["Apple", "Mango", "Orange"];

console.log(fruits.includes("Mango")); // true

7.10 sort()
Sorts array elements.
const numbers = [50, 10, 40, 20];

numbers.sort((a, b) => a - b);

console.log(numbers);

Output:
[10, 20, 40, 50]

Descending:
numbers.sort((a, b) => b - a);

Important: sort() modifies the original array.
7.11 slice()
Extracts a portion of an array without modifying the original.
const numbers = [10, 20, 30, 40, 50];

const result = numbers.slice(1, 3);

console.log(result);

Output:
[20, 30]

The ending index is excluded.
7.12 splice()
Adds, removes or replaces array elements.
const numbers = [10, 20, 30, 40];

numbers.splice(1, 2);

console.log(numbers);

Output:
[10, 40]

It modifies the original array.
7.13 flat()
Flattens nested arrays.
const numbers = [10, [20, 30], [40, 50]];

console.log(numbers.flat());

Output:
[10, 20, 30, 40, 50]

For deeply nested arrays:
const numbers = [10, [20, [30, 40]]];

console.log(numbers.flat(Infinity));

7.14 flatMap()
Maps elements and flattens the resulting array by one level.
const numbers = [1, 2, 3];

const result = numbers.flatMap(n => [n, n * 2]);

console.log(result);

Output:
[1, 2, 2, 4, 3, 6]

PART 8 — Objects and Advanced Object Methods
JavaScript objects are similar to associative arrays in PHP.

Example:
const user = {
    name: "Haris",
    age: 25,
    city: "Pakistan"
};

8.1 Object.keys()
Returns all object keys.
console.log(Object.keys(user));

Output:
["name", "age", "city"]

8.2 Object.values()
Returns all object values.
console.log(Object.values(user));

Output:
["Haris", 25, "Pakistan"]

8.3 Object.entries()
Returns key-value pairs.
console.log(Object.entries(user));

Output:
[
    ["name", "Haris"],
    ["age", 25],
    ["city", "Pakistan"]
]

8.4 Object.fromEntries()
Converts key-value pairs into an object.
const entries = [
    ["name", "Haris"],
    ["age", 25]
];

const user = Object.fromEntries(entries);

console.log(user);

8.5 Object.assign()
Copies properties from one or more objects.
const user = {
    name: "Haris"
};

const updatedUser = Object.assign({}, user, {
    age: 25
});

Modern alternative:
const updatedUser = {
    ...user,
    age: 25
};

8.6 Object.freeze()
Prevents changes to an object itself.
const user = {
    name: "Haris",
    age: 25
};

Object.freeze(user);

user.age = 30; // Does not change in non-strict mode

Note: Object.freeze() is shallow. Nested objects are not automatically frozen.
8.7 Object.seal()
Prevents adding or removing properties, but existing writable properties can still change.
const user = {
    name: "Haris",
    age: 25
};

Object.seal(user);

user.age = 30; // Allowed

user.city = "Wah Cantt"; // Not allowed

PART 9 — Optional Chaining and Nullish Coalescing
These two features are particularly useful when working with APIs.
9.1 Optional Chaining (ES2020)
Suppose an API returns:
const user = {
    name: "Haris",
    address: {
        city: "Wah Cantt"
    }
};

Traditional approach:
if (user && user.address && user.address.city) {
    console.log(user.address.city);
}

Modern approach:
console.log(user?.address?.city);

If an object or property is null or undefined, it safely returns undefined.
Example in React
<p>{user?.address?.city}</p>

This prevents errors when nested API data is missing.

Optional function call:
user?.getDetails?.();

Optional array access:
const firstProduct = products?.[0];

9.2 Nullish Coalescing (??)
Consider:
const username = null;

const name = username ?? "Guest";

console.log(name);

Output:
Guest

It uses the default value only when the left side is null or undefined.
Difference between || and ??
const quantity = 0;

console.log(quantity || 10); // 10

console.log(quantity ?? 10); // 0

Why?

Because || checks falsy values:
- false
- 0
- ""
- null
- undefined
- NaN
Whereas ?? checks only:
- null
- undefined
This distinction is very important when working with API data and user input.
PART 10 — Scope, Hoisting and Closures
These are advanced JavaScript concepts. You should understand them properly because they explain how JavaScript works internally.
10.1 Scope
Scope determines where a variable can be accessed.

JavaScript has three commonly discussed types of scope.

1. Global Scope
const name = "Haris";

function greet() {
    console.log(name);
}

greet();

The variable can be accessed inside the function because it belongs to the global scope.

2. Function Scope
function test() {
    var age = 25;

    console.log(age);
}

test();

console.log(age); // Error

3. Block Scope
if (true) {
    let age = 25;
    const name = "Haris";
}

console.log(age); // Error

10.2 Lexical Scope
Lexical scope means a function can access variables from the scope in which it was defined.

Example:
function outer() {
    const name = "Haris";

    function inner() {
        console.log(name);
    }

    inner();
}

outer();

The inner function can access the outer function's variable.
10.3 Hoisting
Hoisting is JavaScript's behavior of processing declarations before executing code within their scope.

Example with var:
console.log(name);

var name = "Haris";

Output:
undefined

Conceptually, JavaScript handles it approximately like this:
var name;

console.log(name);

name = "Haris";

With let:
console.log(name);

let name = "Haris";

This throws a ReferenceError because let is in the Temporal Dead Zone (TDZ) before its declaration is initialized.
Function hoisting
greet();

function greet() {
    console.log("Hello");
}

This works because function declarations are hoisted with their function definitions.

However:
greet();

const greet = () => {
    console.log("Hello");
};

This throws an error.
10.4 Closures
Closures are one of the most important advanced JavaScript concepts.

A closure occurs when a function retains access to variables from its outer lexical scope, even after that outer function has finished executing.

Example:
function outer() {
    let counter = 0;

    function inner() {
        counter++;

        console.log(counter);
    }

    return inner;
}

const result = outer();

result(); // 1
result(); // 2
result(); // 3

Why does this work?

Normally, you might expect counter to disappear after outer() finishes.

But the returned inner function retains access to its lexical environment.
Real-world uses
Closures are useful for:
- Data privacy
- Maintaining state
- Event handlers
- Callbacks
- Function factories
- React hooks and their state-related behavior
Another example:
function createUser(name) {
    return function() {
        console.log(`Hello ${name}`);
    };
}

const greetHaris = createUser("Haris");

greetHaris();

The returned function remembers the name.
PART 11 — Callback Functions and Higher-Order Functions
11.1 Callback Functions
A callback is a function passed to another function as an argument.

Example:
function greet(name, callback) {
    console.log(`Hello ${name}`);

    callback();
}

function message() {
    console.log("Welcome!");
}

greet("Haris", message);

Output:
Hello Haris
Welcome!

Anonymous callback
greet("Haris", function() {
    console.log("Welcome!");
});

Modern arrow function:
greet("Haris", () => {
    console.log("Welcome!");
});

Where used?
setTimeout(() => {
    console.log("Hello");
}, 2000);

React:
<button onClick={() => console.log("Clicked")}>
    Click
</button>

Node.js:
fs.readFile("file.txt", (error, data) => {
    if (error) throw error;

    console.log(data);
});

11.2 Higher-Order Functions
A higher-order function is a function that:
1. Accepts another function as an argument, or
2. Returns another function.
Example:
function calculate(operation) {
    return operation(10, 20);
}

function add(a, b) {
    return a + b;
}

console.log(calculate(add));

Array methods such as map(), filter() and reduce() are higher-order functions.
Callback vs Higher-Order Function
Callback	Higher-order function
Function passed as an argument	Function accepting or returning another function
Represents the supplied function	Represents the function performing the operation
Example: add passed to calculate	Example: calculate


PART 12 — The this Keyword
This is an important and sometimes confusing JavaScript concept.

this refers to a value determined by how a function is called.
Example 1: Object method
const user = {
    name: "Haris",

    greet() {
        console.log(this.name);
    }
};

user.greet();

Output:
Haris

Here, this refers to the user object.
Example 2: Normal function
function show() {
    console.log(this);
}

show();

In a browser's non-strict script, this generally refers to the global object. In strict mode, it is undefined.
Example 3: Arrow function
Arrow functions don't create their own this.
const user = {
    name: "Haris",

    greet: () => {
        console.log(this.name);
    }
};

user.greet();

This will not behave like the previous object method because the arrow function inherits this from its surrounding scope.

Important: Avoid using arrow functions as object methods when you need this to refer to the object.
call(), apply() and bind()
These methods allow you to control this for regular functions.
const user = {
    name: "Haris"
};

function greet(city) {
    console.log(`${this.name} from ${city}`);
}

Using call:
greet.call(user, "Pakistan");

Using apply:
greet.apply(user, ["Pakistan"]);

Using bind:
const newFunction = greet.bind(user, "Pakistan");

newFunction();

Difference:
Method	Purpose
call()	Calls function immediately with individual arguments
apply()	Calls function immediately with arguments in an array
bind()	Returns a new function with bound this


PART 13 — Promises and Asynchronous JavaScript
This section is extremely important for React, Next.js and Node.js.

First, understand synchronous and asynchronous programming.
13.1 Synchronous JavaScript
Synchronous code executes one operation at a time, in order.
console.log("First");

console.log("Second");

console.log("Third");

Output:
First
Second
Third

13.2 Asynchronous JavaScript
Some operations take time:
- API requests
- Database queries
- File operations
- Timers
- Network requests
JavaScript can handle these operations without requiring the entire program to wait synchronously.

Example:
console.log("First");

setTimeout(() => {
    console.log("Second");
}, 2000);

console.log("Third");

Output:
First
Third
Second

The timer callback runs later.
13.3 What is a Promise?
A Promise represents the eventual result of an asynchronous operation.

A Promise has three states:
State	Meaning
Pending	Operation is still running
Fulfilled	Operation completed successfully
Rejected	Operation failed


Creating a Promise
const myPromise = new Promise((resolve, reject) => {
    const success = true;

    if (success) {
        resolve("Operation successful");
    } else {
        reject("Operation failed");
    }
});

Consuming a Promise
myPromise
    .then((result) => {
        console.log(result);
    })
    .catch((error) => {
        console.log(error);
    })
    .finally(() => {
        console.log("Completed");
    });

Understanding resolve and reject
- resolve() means success.
- reject() means failure.
- .then() handles fulfillment.
- .catch() handles rejection.
- .finally() executes after settlement, regardless of success or failure.
13.4 Promise Chaining
const getUser = () => {
    return Promise.resolve({
        id: 1,
        name: "Haris"
    });
};

getUser()
    .then(user => {
        console.log(user);

        return user.name;
    })
    .then(name => {
        console.log(name);
    })
    .catch(error => {
        console.log(error);
    });

This allows asynchronous operations to be chained.
13.5 Promise.all()
Runs multiple promises concurrently and waits for all of them to fulfill.
const promise1 = Promise.resolve("User");
const promise2 = Promise.resolve("Products");
const promise3 = Promise.resolve("Orders");

Promise.all([
    promise1,
    promise2,
    promise3
])
.then(result => {
    console.log(result);
});

If one rejects, Promise.all() rejects.
13.6 Promise.allSettled()
Waits for all promises to settle, regardless of whether they succeed or fail.
Promise.allSettled([
    Promise.resolve("Success"),
    Promise.reject("Failed")
])
.then(results => {
    console.log(results);
});

13.7 Promise.race()
Returns the result of the first promise to settle.
Promise.race([
    promise1,
    promise2
]).then(result => {
    console.log(result);
});

13.8 Promise.any()
Returns the first fulfilled promise.

Unlike Promise.race(), it ignores rejected promises until a promise fulfills or all reject.
Promise.any([
    Promise.reject("Error"),
    Promise.resolve("Success")
])
.then(result => {
    console.log(result);
});

Promise methods summary
Method	Behavior
Promise.all()	All must fulfill
Promise.allSettled()	Waits for every promise to settle
Promise.race()	First settled promise wins
Promise.any()	First fulfilled promise wins


PART 14 — Async and Await
async and await were introduced in ES2017.

They make asynchronous code easier to read.
Using Promise.then()
function getUser() {
    return fetch("https://jsonplaceholder.typicode.com/users/1")
        .then(response => response.json())
        .then(data => {
            console.log(data);
        });
}

Using async/await
async function getUser() {
    const response = await fetch(
        "https://jsonplaceholder.typicode.com/users/1"
    );

    const data = await response.json();

    console.log(data);
}

getUser();

Much cleaner!
Important concepts
1. async

An async function always returns a Promise.
async function greet() {
    return "Hello";
}

greet().then(result => console.log(result));

2. await

await pauses the execution of its surrounding async function until the Promise settles.

It does not block the entire JavaScript thread.

3. Error handling

Use try/catch.
async function getUser() {
    try {
        const response = await fetch(
            "https://jsonplaceholder.typicode.com/users/1"
        );

        if (!response.ok) {
            throw new Error("Failed to fetch user");
        }

        const data = await response.json();

        console.log(data);

    } catch (error) {
        console.log(error.message);
    }
}

getUser();

Sequential vs Parallel requests
Sequential:
const user = await getUser();
const products = await getProducts();
const orders = await getOrders();

Each operation waits for the previous one.

Parallel:
const [user, products, orders] = await Promise.all([
    getUser(),
    getProducts(),
    getOrders()
]);

The three operations can run concurrently.

This is very important when fetching multiple APIs in Next.js.
PART 15 — Event Loop, Call Stack and Web APIs
This is one of the most important advanced JavaScript concepts.

You should understand it before working deeply with Node.js.

JavaScript is commonly described as a single-threaded language for executing JavaScript code.

But how does it handle asynchronous operations?

The answer involves:
1. Call Stack
2. Web APIs or host APIs
3. Callback Queue (Task Queue)
4. Microtask Queue
5. Event Loop
15.1 Call Stack
The call stack tracks function execution.

Example:
function first() {
    second();
}

function second() {
    console.log("Hello");
}

first();

Execution:
first()
   |
second()
   |
console.log()

Functions are pushed onto the stack and removed when execution completes.
15.2 Web APIs
In browsers, the host environment provides APIs such as:
- setTimeout()
- DOM events
- Fetch API
These operations can be handled outside the JavaScript call stack.

Node.js has its own host APIs and event loop implementation.
15.3 Callback Queue
Callbacks from operations such as timers are queued for execution when ready.
15.4 Microtask Queue
Promise callbacks and other microtasks are scheduled in the microtask queue.

Microtasks generally run before the next task from the task queue.
15.5 Event Loop
The event loop coordinates when queued callbacks can execute.

Consider:
console.log("1");

setTimeout(() => {
    console.log("2");
}, 0);

Promise.resolve().then(() => {
    console.log("3");
});

console.log("4");

Output:
1
4
3
2

Why?

Step by step:
1. console.log("1") executes.
2. setTimeout() schedules a timer callback.
3. Promise .then() schedules a microtask.
4. console.log("4") executes.
5. The current synchronous execution finishes.
6. The Promise microtask executes.
7. The timer callback executes.
This is the foundation of asynchronous JavaScript.

PART 18 — Prototype and Prototypal Inheritance
This is an important concept to understand how JavaScript works internally.

JavaScript uses prototype-based inheritance.

Every ordinary JavaScript object has an internal prototype link, which allows it to inherit properties and methods from another object.

Example:
const user = {
    name: "Haris"
};

console.log(user.toString());

But we never created a toString() method.

Where does it come from?

It comes through the prototype chain.
Prototype example
const animal = {
    eat() {
        console.log("Eating");
    }
};

const dog = Object.create(animal);

dog.bark = function() {
    console.log("Barking");
};

dog.eat();
dog.bark();

The dog object inherits eat() from animal.
Why learn prototypes?
Because:
- Classes use prototypes internally.
- JavaScript inheritance depends on prototypes.
- Many built-in methods come through prototypes.
- Understanding prototypes helps you understand JavaScript deeply.

One important thing: Don't try to learn React, Next.js and advanced JavaScript simultaneously without understanding the JavaScript underneath them.

For example, when you see:
const { data, error } = await fetchProducts();

You should immediately understand:
- const — variable declaration.
- { data, error } — object destructuring.
- await — waiting for a Promise.
- fetchProducts() — function execution.
- = — assignment.
Once you understand these individual concepts, React and Next.js code becomes much easier to read.

Your learning sequence should be:

JavaScript Fundamentals → ES6+ → Advanced JavaScript → React → Next.js → Advanced Next.js.

This will give you a much stronger foundation for professional frontend and full-stack development.
